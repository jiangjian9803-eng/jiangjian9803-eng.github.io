01 / DEFINE THE PROBLEM

Define the problem: make pressure signals read the road.

Research object

Hydro-pneumatic strut-pressure responses of the NTE360A electric haul truck on off-road mine roads.

Core question

When a tire crosses a pothole, how can pressure changes reliably detect the impact, identify its type, and estimate severity?

Unified modeling view
Pothole input→Pressure response→Event detection→Action cue
Physics + signal processing + ML / DL; RL as a future decision layer.
Research goalAn interpretable, verifiable, deployable pothole-monitoring system.
Success criteriaAccurate detection · separable severity · robust across operating conditions.

Proposed contributions

Where the research advances.

01

Repurpose existing sensing.

Use the truck's load-weighing strut-pressure sensors for road monitoring without relying on dedicated cameras or IMUs.

02

Fuse rules with learning.

Let physical thresholds find candidate events, then use ML/DL to reject normal vibration and classify disruption severity.

03

Adapt across conditions.

Normalize pressure response by payload, speed, and operating baseline to improve transfer across routes and truck states.

04

Model multi-strut dynamics.

Learn the timing and pressure relationships among multiple struts to infer event side, type, and maintenance priority.

Feasibility analysis

Build from a working sensing chain—not from scratch.

The graduate project established the truck, pressure-sensing, CAN/J1939, CODESYS, Qt, and field-testing pipeline. The next phase upgrades the analysis layer while preserving that validated engineering foundation.

AvailableHardware & signals

Existing hydro-pneumatic strut sensors already provide synchronized onboard pressure data.

AvailableSystem integration

CAN/J1939 acquisition, controller logic, and HMI workflows provide a practical deployment path.

Feasible nowTraditional ML baseline

Engineered event features can support interpretable SVM, Random Forest, and XGBoost comparisons.

Requires expansionDeep learning dataset

Reliable temporal DL needs more normal-road data, repeated runs, payloads, speeds, and independent routes.

Phase 01 Rebuild labels & baselines→ Phase 02 Benchmark rules vs ML→ Phase 03 Expand field dataset→ Phase 04 Train DL & validate edge inference
Research workflow

A rigorous path from question to reproducible evidence.

Each block is a living research module. Methods, datasets, experiments, and findings will be added as the work progresses.

  1. 01

    Define the question

    Scope the task, outputs, assumptions, constraints, and measurable success criteria.

  2. 02

    Establish the gap

    Review prior methods, compare sensing choices, and state what remains unresolved.

  3. 03

    Design data & ground truth

    Specify acquisition, labels, negative samples, operating conditions, and data quality controls.

  4. 04

    Build traditional baselines

    Create interpretable signal-processing and threshold methods before introducing learning models.

  5. 05

    Develop ML / DL models

    Train increasingly complex models under controlled, leakage-free data splits.

  6. 06

    Evaluate comparatively

    Use consistent metrics, independent tests, error analysis, and statistical uncertainty.

  7. 07

    Test robustness

    Run ablations and stress tests across payloads, speeds, routes, noise, and failure modes.

  8. 08

    Deploy & reproduce

    Measure edge performance and document the data, code, configuration, and limitations.
